# iCloud 参考实现记录

参考为用户保存的 iCloud `2638Build27` 页面。`src/styles/icloud-reference.css` 从其中的 `main.css` 与 `2.main.css` 提取，文件内保留源文件 SHA256。没有复制原站账户内容、登录脚本、云服务请求或原站框架。

`src/styles/integration.css` 仅负责把原规则接入 Vue 与 Grid Layout Plus，以及网站图标、自有设置弹窗等适配。后续修改材质与布局时，先核对原文件，不在应用样式中重复覆盖原规则。

## 从原文件确认的规则

| 视口 | 原站状态 | 内容容器 | 网站卡片 | 图标 |
| --- | --- | --- | --- | --- |
| 小于 760px | SM | 345px | 315px | 4 列，54px |
| 760–1164px | MD | 690px | 315px | 4 列，54px |
| 至少 1165px | LG | 1035px | 660px | 6 列，70px |

编辑工具栏在 1690px 以上使用 1380px 内部容器。它与网站卡片容器不是同一个宽度规则。

首页 bundle 使用 `SM / MD / LG` 判断；只有 LG 使用大卡片。不能把“大于手机宽度”直接等同于“大卡片”。

- 背景结构：白色基底、原始 SVG 纹理及红色 hard-light 混合层。
- 页面结构：固定视口内的独立滚动容器，内容层在背景之上；顶栏在同一滚动内容中 sticky。
- 普通顶栏：`rgba(248,248,252,.4)`，`blur(14px)`。
- 卡片：原始径向渐变，`blur(15px) saturate(86%)`。
- 内容顶部 40px、卡片外边距 15px、内容底部 95px；因此未滚动时首张卡片顶部为 `44 + 40 + 15 = 99px`。
- 普通卡片高 315px。自有网站超过原版容纳的行数后允许增长，避免截断用户数据。
- 内容容器宽度过渡 250ms；卡片尺寸与位置过渡 300ms。
- 编辑工具栏保留 44px 占位，80px 玻璃工具栏从上方滑入，避免顶栏被移除时内容跳位。
- 编辑态白色底层、50% 图标透明度，父容器以原 `jiggly` 关键帧在 ±0.3° 之间往复。
- 卡片只保留原站一次图标投影，不在图标底座叠加第二重阴影。

新增 Cloudflare 额度后，LG 容器内按 660px 网站卡片 + 315px 额度卡片排列，MD 为两张 315px 卡片并排，SM 为纵向排列。仅一张可见卡片时仍居中。Grid Layout Plus 的每个单元包含原版的 15px 外边距，320px 等窄于原版 345px 容器的视口保留防溢出适配。

额度卡片参考原 CSS 的 `.tile` / `.tile .banner`：11px 圆角、80px 标题区、`rgba(248,248,252,.85)`、`blur(15px) saturate(86%)`，内容为白色，投影为 `17px 20px 40px var(--theme-color-boxShadow)`。数据卡片与网站图标卡片各自使用原版对应的材质。

原页面引用的 SF Pro Text 常规与半粗字体已下载为本地资源，避免依赖外链。SF Pro Display 外链不可用，保留原始字体栈及系统回退；中文沿用原字体栈的系统回退。

## 网站栏复刻时的验证

- 浏览器检查 320、393、759、760、1024、1164、1165、1440、1920px 的实际布局，均无横向溢出。
- 用原卡片 DOM 与保存的完整 CSS 建立本地对照，核对手机、桌面的尺寸、位置、内边距、字体栈和材质计算样式。
- 同尺寸截图核对背景、顶栏和卡片边缘的采样位置；图标内容不同，不以整图逐像素相等作为结论。
- 验证卡片滚动到顶栏背后时的真实背景模糊。
- 验证编辑态拖动、设置弹窗、滚动锁定与取消修改。
- `tests/layout.test.ts` 覆盖断点边界、编辑工具栏宽度和额外网站行的高度增长。

## 额度卡片验证

- `tests/quota.test.ts` 覆盖旧配置补充新卡片、隐藏状态保留、九档宽度的布局数据与长网站列表换行，以及真实零值、未知值、超额比例、缓存节流、UTC 重置和失败回退。
- 本地 workerd 接口核对移除/恢复的持久化、版本冲突与未登录访问限制。生产返回 14 项指标，其中 13 项有值；原有 13 个快捷方式及数据库版本保持完整。
- 构建、类型检查与 10 项测试通过。本轮浏览器自动检查被本机工具限制中止，未完成新卡片的浏览器视觉验收。
